# 07-reports：实习报告与阶段材料

本目录用于保存实习报告相关材料，包括报告提纲、阶段总结、图表素材和最终稿。

## 当前阶段材料

- `final-internship-report.md`：最终实习总结正文，标题为《从“得到结果”到“建立证据”：一次科研工程实践中的能力演进》，以能力变化、事实证据和系统溯源为主线。
- `internship-content-review-by-technical-route.md`：截至 2026-08-27 的实习内容总盘点，按技术路线而非日期重组；作为最终报告/PPT的事实底稿。
- `internship-report-outline.md`：早期报告提纲，仅保留为历史结构参考，不作为当前终稿结构。

## 报告材料来源

最终实习报告主要来自以下目录：

- `01-daily-log/`：全过程日志；
- `01-daily-log/weekly-review/`：周总结与阶段成果；
- `02-meetings/`：组会记录；
- `03-notes/`：理论基础；
- `04-literature/`：文献调研；

## 当前最终报告主线

```text
软件使用者
→ 工程接手者

→ 故障诊断者

```

正文强调“问题—证据—根因—能力变化”，避免按8周流水账展开。本人职责边界需保持清楚：不承担上游 FLUKA 粒子输运计算，重点在其结果向下游热工仿真、接口验证、CAD/网格诊断和实验约束的工程衔接。

## 写作原则

- 过程真实、任务明确、成果可追溯；
- 用数据支撑判断，不用情绪化叙述替代事实；
- 区分“已运行、已验证、基本定位、未完成”；
- 不把阶段故障定位写成完整工程计算闭环；
- 不用空泛的“收获很大、受益匪浅”替代能力变化；
- 对 AI、GitHub 等工具同时评估效率、认知风险与科研责任。

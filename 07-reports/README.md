# 07-reports：实习报告与阶段材料

本目录保存实习成果的正式文字载体。

## 当前主文件

- `final-internship-report.md`：最终实习总结正文，《从“得到结果”到“建立证据”：一次科研工程实践中的能力演进》；
- `internship-content-review-by-technical-route.md`：按技术路线整理的事实底稿，用于核对最终报告和 PPT。

早期 `internship-report-outline.md` 已被最终结构替代，现归档于 `09-archive/reports/internship-report-outline-early.md`。

## 最终报告主线

```text
软件使用者
→ 工程接手者
→ 结果验证者
→ 故障诊断者
→ 具备系统维护与科研协作意识的责任节点
```

职责边界保持明确：本人基于团队上游 FLUKA 粒子输运结果，重点负责其向下游热工仿真、接口验证、CAD / 网格诊断和实验约束的工程衔接。

## 事实来源

- `01-daily-log/`：终版事实日志；
- `01-daily-log/weekly-review/`：周度归纳；
- `02-meetings/`：实际组会记录；
- `04-literature/`：论文与外部文献证据；
- `05-software/`：软件学习记录；
- `06-cases/`：历史算例和运行记录；
- `10-handoff/`：工程停点与续接说明。

## 写作原则

- 用数据支撑判断，不用情绪叙述替代事实；
- 区分“已运行、已验证、基本定位、未完成”；
- 不把团队上游成果写成个人完成内容；
- 不把阶段故障定位写成完整工程计算闭环；
- AI / GitHub 的价值与风险均以本项目实际使用证据评价。

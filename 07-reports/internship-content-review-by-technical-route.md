```text

        ↓

        ↓

        ↓
```

## 2. 技术路线 A：从 Ansys 入门到理解已有工程模型

### 2.1 软件能力建立

第1周从 Workbench/Fluent 最小案例入手，完成二维、三维模型的几何、网格、边界条件、初始化、瞬态计算与结果输出，并读取已有 Fluent→Mechanical 耦合工程。此阶段的成果不是某个最终数值，而是获得了“能打开、能运行、能检查已有模型”的基本能力。

### 2.2 论文与工程基线

第2周精读《CiADS缪子源靶后高功率准直器设计》，把零散软件操作放回完整物理链中理解：

```text
束流/准直结构
→ 粒子输运与能量沉积
→ 热源转换
→ 温度/流场
→ 热应力
→ 偏移与机器保护
```

由此明确本次实习的合理任务不是重新设计整套准直器，而是接手已有热工计算链，恢复接口、验证物理正确性并为工程拓展建立可追溯基线。

## 3. 技术路线 B：恢复并验证旧 FLUKA→Fluent 热源链

### 3.1 接口恢复

第3周围绕旧 `.29` 数据完成：

- `.29 → Python → heat_deposition.c/.h` 数据转换；
- 重建 `DEFINE_SOURCE` 热源 UDF；
- 编译、加载 `libudf`；
- 将热源挂接到铜质 source 区；
- 跑通可重启的 Fluent 基线。

这一步证明了“软件链能够工作”，但当时仍不能证明功率与坐标映射是物理正确的。

### 3.2 从“能跑”进入“物理验证”

第4周建立并行诊断 UDF，区分了三个过去容易混淆的量：

- FLUKA 完整规则计分盒功率：约 **46.800 kW**；
- zones 8–11 按同一映射算法得到的诊断功率：约 **38.178 kW**；
- Fluent 真正挂载于 zone 10 铜区的功率：约 **37.243 kW**。

完整盒与 zones 8–11 之间的净差为 **18.422%**。进一步诊断表明：

- zone 10 单元/体积覆盖接近 100%，不是“漏了18%的单元”；
- 完全空体素仅贡献约 0.062% 总功率；
- 正缺失功率约 9.496 kW；
- 过填充补偿约 0.875 kW；
- 二者相减闭合为约 8.621 kW 净缺口。

因此阶段结论被修正为：

> 功率差主要由 Fluent 实际几何与 FLUKA 规则计分盒不完全重合，以及“以 Fluent 单元质心决定所属 FLUKA 体素”的非严格体积守恒映射共同造成，而不是简单漏映射。

这是旧模型阶段最重要的物理验证成果。

## 4. 技术路线 C：新 FLUKA 数据接口从文本链改为原始二进制直读

第6周获得新几何与新 FLUKA 数据后，旧的 20×20×28、1 cm voxel 静态 C 数组方案不再适用。新 Cartesian 计分名义规模为：

```text
300 × 300 × 384
1 mm × 1 mm × 1 mm
```

最初尝试读取 `.30.lis`，但第7周通过 Python 与 Fluent 双重验证发现：

- 理论应有 34,560,000 个数据；
- `.30.lis` 仅含 14,786,930 个完整数值；
- 覆盖率仅 **42.786%**；
- 与原始矩阵前缀逐项匹配，因此它只是被截断的 ASCII 输出。

随后直接解析原始 `fort.30`：

- 确认 Fortran sequential record 结构；
- 第三个 record 恰为 34,560,000 个 float32；
- Python 与 Fluent UDF 对数量、总和、峰值与 Hash 全部一致；
- UDF static memory 跨 On-Demand 调用保持稳定。

按 5 mA 工况换算后，在 Fluent 内得到：

- 全域积分沉积功率约 **31.035 kW**；
- 峰值体热源约 **3.584×10^7 W/m³**。

正式数据路线由此固定为：

```text
FLUKA 原始 fort.30
→ Fortran record 解析
→ 34,560,000 float32
→ UDF static memory
→ 5 mA 归一化
→ 坐标映射
→ DEFINE_SOURCE
```

其中“数据读取与单位归一化”已经闭环，“正式 CAD↔FLUKA 三维坐标映射”仍待新几何完成后验证。

## 5. 技术路线 D：新 CAD / Fluent Meshing 问题从调参追溯到实体拓扑

### 5.1 初期误区：把 Share Topology 失败当作网格精度问题

新几何导入后，Fluent Share Topology 长期出现：

- non-manifold；
- self-intersection / dihedral violation；
- node insertion failed；
- topology corrupted；
- SIGSEGV。

曾测试减小 Minimum Size、曲率角、Gap Distance，以及 Join Only / Join and Intersect，但没有根治问题。0.5 mm 局部加密反而使失败扩散，证明“继续加密”不是主方向。

### 5.2 CAD 几何级实证

SpaceClaim 横截面、Overlap/Combine 等检查确认部分冷却管与铜体存在真实体积穿模。针对单管建立“两刀法”：

1. 清除 `Cu ∩ pipe wall`；
2. 清除 `Cu ∩ pipe lumen`；

从而同时保证钢管壁不与铜体占据同一体积、Ø12 mm 管腔连续贯通。

进一步发现更深层问题：若干三维螺旋空心管与圆柱主体被做成同一个连续 Solid，原本应存在的管—铜内部界面被 Boolean 合并。由此确认机械 CAD 不能直接等价为 CFD 可用几何。

### 5.3 Fluent TUI 局部诊断与 A/B 验证

后期不再依靠 GUI 猜测，而是用 TUI 分开检查：

- inter-zone intersection；
- self-intersection；
- duplicate faces；
- Local Join 候选面。

在新版 `.x_t` 上：

- `wall.5 / wall.6` 与主体存在数万级 inter-zone intersection；
- self-intersection = 0；
- duplicate = 0；
- `wall.7 = 0 intersection`，形成同模型健康对照。

删除可疑管路后重新生成 Surface Mesh，Share Topology 能完成 Join/Intersect 与 region computation，不再触发原有 topology corrupted / SIGSEGV。该 A/B 结果强烈支持：局部管—主体接口是主导故障源。

### 5.4 当前停点

Share 主故障被压下后，新问题转移到 Capping：重新网格后旧入口/出口 Face Zone 身份失效。Bounding Box 仍证明长细管存在，因此不是 CAD/Surface Mesh 把管子“截没了”，而是 Guided Workflow 保存的旧 zone 选择已经失效。

当前后续严格起点：

```text
重新识别长管端面
→ Capping
→ 流体 Region
→ Volume Mesh
→ 新 Cell Zone
→ UDF 挂接
→ 功率积分
→ Solver
```

## 6. 技术路线 E：DRPL-V 热物性实验从“测 K”转为“验证测量系统”

8 月 19–26 日开展平板热流计实验。早期数据曾表现出明显非单调压力效应和异常低值，但补测后多数异常无法重复，说明装夹、接触热阻与实验状态的影响不可忽略。

阶段性认识如下：

- 在约 76–179 kPa 范围内，没有得到稳定、可重复的 `K-P` 单调规律；
- 温度响应比压力效应稳定，更适合先建立 `K_eff(T)`；
- 测得量应称为封装结构厚度方向**等效导热系数**，不能直接当作单一铝/不锈钢的本征导热率。

8 月 25 日 1号片在 35 ℃、100 ℃出现“首轮偏高、后续收敛”，但 200 ℃未出现；8 月 26 日 2号片也未复现固定首轮高值，因此“首轮虚高”不能视为仪器固有偏差。

现场观察到挂壁水珠、试样水雾后，湿度与凝露被正式列为系统误差边界。可能机制包括：

- 液膜改变接触热阻；
- 边缘水膜形成旁路导热；
- 凝结/蒸发潜热与局部自然对流破坏稳态假设。

当前对 DRPL-V 的评价应分层：

- 温控与加载稳定性：较好；
- 稳态短期重复性：较好；
- 绝对准确度：未闭环；
- 湿度/凝露鲁棒性：未闭环；
- 厚度读数随温度明显漂移：仍需设备侧解释。

因此实验支线已经给热工仿真提供“如何使用数据”的边界，而不是给出一个未经验证的单一材料常数。

## 7. 实习期间形成的工程方法，比单个软件结果更具复用价值

整个实习的排障方法发生了明显变化。

早期更接近：

```text
报错 → 改参数 → 再运行
```

后期逐步形成：

```text
定义问题
→ 保存基线
→ 分离变量
→ 独立诊断
→ 数量/功率守恒
→ 健康对照
→ A/B 修改
→ 回归验证
→ 再进入下游步骤
```

具体体现为：

- 区分“完整 FLUKA 功率 / 诊断映射功率 / Fluent 实际加载功率”；
- 用 Python 与 Fluent 两条独立路径交叉验证原始二进制数据；
- 用逐体素收支而不是凭温度结果猜测映射错误；
- 用 self / duplicate / inter-zone 三类 TUI 诊断分离网格问题；
- 用删除单管的 A/B 试验判断几何故障源；
- 实验中把“随机噪声、条件性过渡偏差、环境系统误差”区分开。

这套方法可直接作为后续接手复杂多软件工程链时的通用工作框架。

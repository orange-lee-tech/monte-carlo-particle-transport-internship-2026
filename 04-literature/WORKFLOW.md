# 文献知识库工作流

更新时间：2026-07-10

## 1. 核心原则

聊天窗口只用于即时协作，不作为长期事实库。

以下内容一旦形成，应尽快沉淀到 GitHub：

- 单篇文献的关键事实、数据、图表和页码；
- 对文献方法、假设和局限性的解读；
- 跨文献对比结论；
- 对当前设备方案有直接影响的判断；
- 组内分享提纲和可复用图表清单；
- 尚待核查的矛盾、缺口和问题链。

不应只保留在对话中的内容：

- 关键参数；
- 重要设计逻辑；
- 已经完成的批判性分析；
- 后续需要反复引用的判断；
- 文献之间的对应关系。

## 2. GitHub读取习惯

开始新阶段、切换对话或回答重要技术问题前，主动读取：

1. `WORKING_RULES.md`
2. `00-admin/current-task.md`
3. `04-literature/index.md`
4. 与问题相关的单篇文献笔记
5. 已有专题综合文件

不得等待用户重复提醒，也不得仅凭聊天记忆复述长期结论。

## 3. 单篇PDF处理流程

### A. 登记

收到 PDF 后先在 `04-literature/index.md` 登记：

- 文献ID；
- 标题；
- 原始文件名；
- 本地所在文件夹；
- 主题标签；
- 状态；
- 笔记路径。

### B. 页码地图

先读目录、摘要、结论、图表目录和高相关章节，形成页码地图。长文档禁止无目的全文展开。

### C. 精读

优先抽取：

- 装置背景和功能；
- 束流参数；
- 几何结构；
- 材料与制造状态；
- 能量沉积；
- 冷却条件；
- 温度、应力、变形；
- 正常、偏移和事故工况；
- 机器保护；
- 作者承认的不确定性。

### D. 形成笔记

单篇笔记存放于：

```text
04-literature/notes/
```

命名格式：

```text
LIT-编号-简短英文主题.md
```

### E. 专题综合

至少三篇高度相关文献完成后，再建立：

```text
04-literature/synthesis/
```

专题文件不重复摘抄全文，而回答明确工程问题，例如：

- 多级准直器如何分配热负荷；
- 孔径扩大为何可能降低或增加下游束损；
- OFHC、GLIDCOP及制造态材料参数如何选择；
- 束流位置偏移和角度偏转哪个更危险；
- 冷却流速、压降和冲蚀如何权衡。

## 4. 证据要求

所有重要结论应尽量保留：

- PDF页码；
- 章节标题；
- 图号；
- 表号；
- 原始数值；
- 单位；
- 适用工况。

必须明确区分：

- **文献事实**：作者明确报告的内容；
- **我们的判断**：基于文献作出的解释或推断；
- **疑点**：文献内部不一致、假设过强或证据不足；
- **待核查**：需要其他文献、模型或实验确认的问题。

## 5. PDF与Markdown的边界

不默认把整篇 PDF 全文转为 Markdown。原因：

- 浪费存储和处理资源；
- 重复原文，降低知识密度；
- 容易丢失图表、公式和版式语义；
- 后续检索结果噪声过高。

Markdown只保存经过筛选的高价值内容，PDF继续作为原始证据源。

不直接修改原始 PDF 插入标签。标签、页码地图和解释统一放在 GitHub 索引和笔记中，避免破坏证据源并减少版本混乱。

## 6. 上传请求格式

后续要求上传文献时，必须同时说明：

| 项目 | 必须提供 |
|---|---|
| 文件名 | 精确名称 |
| 所在文件夹 | 基于用户提供的目录树给出完整相对或绝对路径 |
| 优先级 | 当前上传顺序 |
| 选择理由 | 该文献填补什么知识缺口 |
| 预期产出 | 页码地图、单篇笔记、对比表或专题综合 |

## 7. 质量控制

- 不把会议论文中的方案直接当作最终工程定型。
- 不把某装置的联锁时间、温度限值、流速限值直接移植到当前设备。
- 不只记录“结果好不好”，还要记录模型假设和材料状态。
- 发现正文与表格数值不一致时，必须显式标记。
- 重要结论至少尝试由两类证据交叉支撑：设计报告、论文、实验数据或现有计算文件。
- 组内分享材料应能追溯到单篇笔记和原始PDF页码。

## 8. 深度阅读与内化原则

后续论文阅读不以“逐篇看懂并摘录”为终点，而应形成三层成果：

1. **单篇理解**：明确作者解决了什么问题、用了什么方法、得到了什么结果；
2. **专题内化**：把多篇文献中的共性方法、分歧、适用条件和风险组织成稳定框架；
3. **设计转化**：把可迁移的方法论、建模思路、验证路线和风险预告转化为当前设备的设计输入与工况清单。

文献阅读的主要价值是：

- 同步国内外较先进的方法论；
- 了解已有研究成果和工程实现路径；
- 提前识别必须面对的困难、失效模式和验证要求；
- 避免重复已经被证明无效或代价过高的路线；
- 在已有工作基础上提出适合当前设备的新方案。

## 9. 参数使用原则

文献中的具体参数主要用于理解量级、物理机制和工程约束，不作为当前设备的直接设计值。

原因包括：

- 束流能量、功率、束斑和时间结构不同；
- 几何、材料、冷却和制造状态不同；
- 设备可能存在保密或未公开参数；
- 当前设备的关键参数最终需要由本地粒子输运、流体和热结构模型计算得到。

因此，引用参数时必须说明其用途：

- **量级参照**；
- **方法验证**；
- **风险预告**；
- **边界条件来源**；
- **当前方案对比**。

不得将他装置的温度、流速、联锁时间、应力限值或几何尺寸直接移植为当前设备设计值。

## 10. 对话交接原则

文献深度阅读可在独立新对话中进行，以减少上下文干扰。新对话开始前应先读取：

1. `04-literature/WORKFLOW.md`
2. `04-literature/index.md`
3. `00-admin/current-task.md`
4. 已有 `notes/` 和 `synthesis/` 中与当前主题相关的文件
5. 专门的阶段交接文件

新对话不重新从聊天历史恢复结论，而以 GitHub 知识库作为唯一长期基线。

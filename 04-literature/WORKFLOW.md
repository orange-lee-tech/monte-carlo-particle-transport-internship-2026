# 文献知识库工作流

> 实习现场阶段已经结束。本工作流当前用于维护证据边界和未来按需阅读，不再要求沿旧“先复现论文、再依次精读外部文献”的计划机械推进。

## 1. 唯一入口

`04-literature/`是文献管理唯一入口。原`05-reference/`已合并，不再维护平行索引、模板和缓存目录。

开始文献相关工作前读取：

1. `04-literature/README.md`
2. `04-literature/index.md`
3. 与当前任务相关的`deep-reading/`、`notes/`和`synthesis/`
4. `00-admin/current-task.md`

## 2. 两类文献

### 直接继承基线

用于当前模型复现和工程接手，例如帅文文论文。需要建立独立`deep-reading/LIT-xxx/`数据栈，并与代码、算例和验证报告互相链接。

### 外部方法支撑

用于同步方法、了解已有成果和识别风险。当前LIT-003—LIT-010仅完成机器辅助结构化整理，待基线继承后再开展用户人工精读。

## 3. 单篇状态

| 状态 | 含义 |
|---|---|
| 已登记 | 原始文件或书目信息存在 |
| 已建页码地图 | 已定位重点章节 |
| 机器辅助笔记完成 | 已形成结构化摘要，但用户未必人工阅读 |
| 用户人工精读 | 用户已完成阅读和理解校正 |
| 工程继承中 | 已与代码、模型和运行记录建立对应 |
| 基线复现完成 | 关键锚点工况可重复得到 |
| 已用于拓展 | 已进入新方案、新工况或新方法 |

## 4. 核心文献数据栈

```text
deep-reading/LIT-xxx-title/
├── README.md
├── source-manifest.md
├── source-map.md
├── reading-notes.md
├── inheritance-map.md
└── corrections-and-open-questions.md
```

不再保留独立`cache/`目录。临时阅读内容在对话或本地处理，形成稳定结论后再写入正式文件。

## 5. 证据分层

必须区分：

- **论文事实**：作者明确报告，保留页码、图号、表号和工况；
- **用户理解**：用户基于阅读形成的解释；
- **工程验证**：来自代码、自动测试、Fluent/Mechanical运行或实验；
- **待核实**：论文、代码和模型之间尚未闭合的问题。

论文正文回答“作者做了什么”；计算文件回答“如何实现”；自动验证和运行记录回答“当前仓库是否真正复现”。

## 6. 参数原则

他装置的尺寸、流速、温度、应力和保护时间只用于：

- 量级检查；
- 方法借鉴；
- 风险预告；
- 回归测试；
- 变量扫描设计。

当前设备设计值必须由本地束流、输运、流体和热结构模型产生。

## 7. 当前使用顺序

```text
遇到明确工程问题
→ 先查 07-reports / 10-handoff 的现有证据
→ 需要论文依据时回到 LIT-001
→ 需要外部方法比较时再查 LIT-003—LIT-010
→ 必要时补人工精读
→ 新结论重新区分“文献事实 / 工程验证 / 待核实”
```

# 实习日志记录规则

更新时间：2026-07-07

## 1. 基本原则

每日实习日志必须基于真实发生的工作内容，以及用户与助手之间的明确聊天信息撰写。

日志中不扩展未发生的内容，不猜测用户想法，不把尚未执行的计划写成已经完成的事实。

## 2. 每日记录方式

实习周期内，每天建立一个 Markdown 文件。

命名方式：

```text
YYYY-MM-DD.md
```

例如：

```text
2026-07-07.md
```

## 3. 当天过程记录

在当天工作过程中，可以向当天日志文件追加内容，形成过程记录。

要求：

- 每次追加内容应当有限；
- 记录发生过的事实；
- 不要求一开始格式完美；
- 最终版本再统一整理格式。

## 4. 当天终版日志

每天结束时，用户会与助手讨论当天工作内容，并生成当天终版日志。

终版日志生成后，原则上不再修改。

## 5. 历史日志权限

已明确终版的历史日志不得修改。

当前规定：

- `2026-07-06.md` 已视为终版，不再修改；
- `2026-07-07.md` 当前仍处于当天过程记录阶段，可继续追加；
- 当 7 月 7 日终版日志生成后，也不再修改。

## 6. 写作风格

日志风格要求：

```text
格式简单
内容具体
无废话
不堆字数
可追溯
只记录实际发生和明确交代的内容
```

## 7. 不应写入日志的内容

- 没有发生的工作；
- 没有被用户确认的推测；
- 助手自行脑补的心理活动；
- 未公开的单位内部敏感信息；
- 账号、密码、服务器地址、VPN 配置等敏感信息。
